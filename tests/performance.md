# Производительность полного запуска тестов

Замер 25.10.2026, Windows, PHP 8.4 CLI, локальный MySQL 9.1.
Актуальная команда без фильтра наборов: `test.bat --no-colors --xml=profile-all-open.xml`.

## Актуальный результат: RBAC включается только в проверках авторизации

**253,060 с (4 мин 13 с), 2599 тестов, 10569 assertions.**
Обычные тесты используют `useRBAC=false`, `authorizedView=false`.
`AuthorizationModesCest` продолжает временно включать нужный режим и возвращает
исходный файл; все 4 проверки режимов прошли. Unit-матрицы доступа также
продолжают переключать параметры в памяти и восстанавливать их в `finally`.

| Набор | Тестов | Время самих проверок JUnit, с | Результат |
|---|---:|---:|---|
| acceptance-extra | 3 | 0,703 | Без падений |
| acceptance | 1100 | 105,593 | Без падений, 7 пропусков |
| functional | 0 | 0 | Пока пустой |
| migrations | 1 | 29,264 | 193 миграции проекта, 587 assertions, без падений |
| rest | 245 | 8,969 | Без падений, 37 пропусков |
| unit | 1250 | 36,994 | 2 ошибки, 2 падения |

Все 693 HTTP-падения с ответом 401 устранены корректным режимом тестов.
Теперь REST выполняет операции записи; его прежние 0,881 с при ответах 401
не были временем успешного CRUD. В полном прогоне остаются 2 ошибки
`NetworkGenerationTest` (отсутствует роль `local`) и 2 падения:
`DocsHelperTest::testRenderSectionCache`,
`NetVlansReservationTest::testDomainReusesVlanSearch`.

После полного запуска `config/params-test.php` совпал байт-в-байт с исходником
нового открытого режима. Диагностика: `tests/log/profile-all-open.xml` и
`tests/log/profile-all-open-console.txt`.

**Времена JUnit не включают подготовку наборов, построение data provider,
импорт дампа и финальный отчёт.** Их сумма — 165,441 с; вместе с остальными
этапами полный запуск занимает 257,017 с. Это не замер только unit.

В предыдущем замере было 2 ошибки, 697 падений, 44 пропуска. Все 693 HTTP-падения
содержали ответ 401: тогда `config/params-test.php` включал `useRBAC=true`,
а эти сценарии ожидают режим без RBAC. Исходный файл параметров сохранён
байт-в-байт. Остальные падения — IntegrationsSmsTest (2), DocsHelperTest и
NetVlansReservationTest; 2 ошибки — NetworkGenerationTest (`roles['local']`).
По тому запуску нельзя оценивать длительность успешных операций записи REST:
401 возвращается до выполнения самой операции.

## Что обнаружено и исправлено

1. Исходный `test.bat` использовал Apache с Xdebug `mode=debug` и
   `start_with_request=1`: обычные HTTP-сценарии занимали 2,4–2,8 с.
   Замер остановлен на 242 с в начале acceptance; исходное полное время
   **не измерено**. Новый запуск поднимает собственный PHP-сервер на свободном
   порту; внешний сервер по `ARMS_TEST_SERVER_URL` остаётся доступным вариантом.
2. Debug toolbar, подробные SQL-логи и backtrace не участвуют в assertions,
   но создают большой расход памяти и времени. В тестовом web-конфиге остаются
   ошибки и предупреждения; `error_reporting(E_ALL)` сохранён. Ресурсы и сессии
   тестов изолированы от файлов Apache. На HTTP-сервере включён OPcache.
3. Кэш схемы в console/web тестах приводил к чтению старых столбцов после
   пересоздания БД. Из-за этого migrations падал на `state_id`; кэш отключён
   именно в тестовых конфигах. Исходники миграций не менялись.
4. После удаления БД набором migrations следующий набор не мог подключиться
   к `dbname=arms_test` для импорта. `loadSqlDump()` теперь сначала гарантирует
   существование БД через management-соединение. Это одна подготовка на импорт,
   а не восстановление дампа перед отдельными сценариями.
5. REST-модуль добавляет полный body упавшего ответа в консольные артефакты.
   После выполнения тестов стандартный reporter форматировал сотни HTML-страниц:
   промежуточный полный запуск занял **627,696 с**, из них около 361 с —
   финальная печать результатов. `Helper\ResponseReport` заменяет большие body
   путями к полным `.fail.html`/`.fail.json`; короткие ответы остаются в консоли.
   Размер консольного лога уменьшился с 19,5 до 1,2 МБ.
6. Проверка BOM отсекает `vendor` до рекурсивного обхода; список проверяемых
   PHP-файлов проекта сохраняется.

Сравнительные полные прогоны до/после компактного отчёта дали одинаковые
2599 тестов, 10375 assertions, 2 ошибки, 697 падений и 44 пропуска. Списки
упавших сценариев совпали. Ошибки не скрываются и не превращаются в успех.

## Что ещё занимает время

Acceptance остаётся основным набором: 1100 HTTP-сценариев, включая реальное
обращение к Wiki (`site/wiki`, около 11 с), сканирование сети
(`network-map/scan`, около 4 с) и построение Swagger (`site/api-json`, около
1,8 с). Набор миграций требует около 30 с на применение всей цепочки к пустой
БД; он продолжает проверять состояние одного соединения после каждого шага.
Подготовка схемы и генерация связанных CRUD-моделей также остаются частью
полного времени. Эти проверки и глубина генерации не сокращались.

Открытый режим для обычных тестов теперь задан явно; актуальный полный замер
с успешными HTTP CRUD-проверками приведён в начале документа.

Артефакты замера (gitignored):
- `tests/log/profile-all-compact.xml` — JUnit по всем наборам;
- `tests/log/profile-all-compact-console.txt` — финальный консольный отчёт;
- `tests/log/profile-all-final.xml` и `profile-all-final-console.txt` — сравнение
  со стандартной печатью полного body;
- `tests/log/profile-all-baseline.txt` — остановленный исходный запуск на Apache.
