# Временные доступы

Полезно для учёта доступов пользователей к сервисам / IP-адресам / компьютерам.
Доступ через меню **Доступы -> Временные доступы**.

Как устроено: временный доступ — это расписание, к которому привязаны
[списки доступа (ACL)](../models/acls.md); каждый ACL описывает один ресурс
и содержит [записи доступа (ACE)](../models/aces.md) — кто и какой доступ
получает. Подробнее о сущностях — на их страницах, обзор всех сценариев
учёта доступов — в руководстве «[Контроль доступа](access-control.md)»,
здесь — пошаговый сценарий работы.

## Добавление

Кнопка **«Добавить»** в списке временных доступов открывает единую форму:
наименование и заметки доступа, участники (кто и какой доступ получает)
и ресурсы (куда). Всё создаётся одним сохранением: расписание, по одному
ACL на каждый выбранный ресурс и записи доступа в них.

Если у выбранного сервиса-ресурса заданы **типы доступа по умолчанию**
(настраиваются в карточке сервиса), галочки этих типов проставляются в форме
автоматически — их всегда можно снять или дополнить вручную. Если у сервиса
для типа переопределены сетевые параметры (например HTTPS на нестандартном
порту — «TCP 8140»), предзаполняются именно они, а не параметры типа
по умолчанию.

Если ресурсов выбрано несколько, созданные ACL получают одинаковый набор
записей и образуют **группу** — на странице временного доступа они
показываются одной карточкой «N ресурсов» (см. «Просмотр»).

Периоды действия доступа добавляются после создания — на странице
просмотра.

### Подсказка

При планировании большого количества сложных временных доступов надо учитывать, что удобнее всего их разделять по проектам. Например, ООО «Рога и копыта» должны внедрить новый функционал интеграции 1C ERP и Jira:

- Заводим контрагента и его сотрудников, среди них есть:
  - Специалист по 1С
  - Специалист по Jira
  - Специалист по протоколу интеграции
- Заводим временный доступ «Удалённый доступ ООО Рога и копыта по проекту интеграции 1С и Jira». В нём заводим:
  - ACL-списки:
    - Специалист по 1С
      - доступ по VPN, доступ уровня админа
        - к 1С DEV-окружение
      - доступ по VPN, доступ на чтение
        - к 1C продуктив
    - Специалист по Jira
      - доступ по VPN, доступ уровня админа
        - к Jira DEV-окружение
      - доступ по VPN, доступ на чтение
        - к Jira продуктив
    - Специалист по протоколу интеграции
      - доступ по VPN, доступ уровня админа
        - к 1С DEV-окружение
        - к Jira DEV-окружение
      - доступ по VPN, доступ на чтение
        - к Jira продуктив
        - к 1C продуктив
  - Период доступа на срок реализации проекта
    - а также все периоды, на которые проект продляется
    - периоды дополнительного сотрудничества в том же качестве

Почему удобно именно так? Потому что такие комплексные доступы обычно продляются ровно в таком же виде, а для этого достаточно в уже готовом временном доступе просто добавить период доступа.

## Копирование и шаблоны

Кнопка копирования (иконка рядом с названием на странице временного доступа)
создаёт **глубокую копию**: новое расписание со всеми списками и записями
доступа образца. В форме копии можно сразу **заменить субъектов** — тогда во
всех скопированных записях доступ получат указанные сотрудники (персональные
IP образца не переносятся). Периоды действия образца не копируются — новые
периоды задаются на странице созданного доступа.

Это покрывает два сценария:

- **Повторить служебку**: очередная согласованная записка с типовым набором —
  копируем прошлый временный доступ, меняем сотрудника и добавляем период.
- **Шаблоны**: заводится временный доступ-образец без реальных субъектов
  (например «Шаблон: стандартный удалённый доступ», в записях доступа вместо
  субъекта — пометка в поле «Прочее») и без периодов. Выдача доступа по
  шаблону — копия с подменой субъектов.

## Просмотр / Редактирование

В окне просмотра слева располагаются списки доступа (ACL):

- комбинация ресурса, к которому предоставляется доступ,
- и одной или нескольких записей доступа (ACE) — комбинаций **кто** и **какой** доступ к ресурсу получает.

Т.е. тут отображается (и настраивается), кто, куда и какой доступ получает в рамках этого временного предоставления доступа.

ACL с одинаковым набором записей объединяются в **группу** — одна карточка
«N ресурсов». Переключатель **«Группировать / Детально»** показывает их
одной карточкой или каждый ACL отдельно. Правки участников группы
(добавление, изменение, удаление записей) и состава ресурсов применяются
сразу ко всем ACL группы.

В правой половине окна просмотра отображаются периоды **предоставления**
(зелёные) и **отзыва** (красные) доступа и заметки по этому временному
доступу (если внесены). Индикатор показывает, действует ли доступ прямо
сейчас. Продление доступа — добавление нового периода (кнопка
«Добавить период»).

## Добавление и заполнение отдельного ACL

Добавить ресурс в существующий временный доступ можно кнопкой «Добавить»
под списком ACL: в форме сразу заполняются и участники (записи доступа),
и один или несколько ресурсов — на каждый ресурс создаётся отдельный ACL.

Дозаполнить существующий ACL записями можно кнопкой добавления записи
на его карточке (в группе — «Добавить участников»: запись добавится во
все ACL группы).
