# Обновление

Порядок обновления установленной вручную системы: git pull, обновление зависимостей, миграции БД, а также откат обновления, если что-то пошло не так.

Для чистой [установки](install.md) есть отдельная инструкция.

### Перед обновлением

Если мы хотим, чтобы обновления были обратимы, то

Смотрим на каком коммите мы находимся:

```bash
git log -1
```

и запоминаем (лучше в файл) хэш текущего коммита (например c729a2b43520275f1abc8c25bd9770f5d6c43519)

Если страшно, то можно сделать [резервную копию](backup.md)

### Обновление файловой структуры

Просто скачиваем свежую версию при помощи git:

```bash
git pull
```

После этого обновляем зависимости

```bash
composer update
```

С этого места система в общем случае неконсистентна, поэтому быстро обновляем структуру БД:

```bash
./yii migrate
```

Собственно все. Система снова консистентна и находится в последней версии.

### Переход на адреса без /web

Инсталляции, развернутые по прежней инструкции, публиковались с DocumentRoot в корне проекта:
запросы переписывал в подпапку `web` лежащий там `.htaccess`, и во всех адресах оседал лишний
токен - `https://inventory.domain.local/web/techs/index`. Канон теперь - DocumentRoot в самой
подпапке `web`, адреса без `/web` ([установка](install.md#адреса-приложения)).

Переход не обязателен и не срочен: **старые адреса работают в любом случае**, менять их
в интеграциях можно постепенно. Но выполнить его стоит - хотя бы потому, что при DocumentRoot
в корне проекта в зоне досягаемости веб-сервера оказываются исходники, `config/db-local.php`
с паролем БД и `runtime`.

Вариант 1 - **сменить DocumentRoot** (рекомендуется). В конфиге виртуального хоста apache
меняем корень сайта и блок `<Directory>` на подпапку `web`:

```apache
DocumentRoot "/var/www/arms/web"

<Directory "/var/www/arms/web">
  Options -Indexes +Includes
  AllowOverride All
  Require all granted
</Directory>
```

и перечитываем конфигурацию:

```bash
apachectl configtest && systemctl reload apache2
```

Вариант 2 - **если доступа к конфигу веб-сервера нет**. Оставляем DocumentRoot в корне проекта
(его `.htaccess` продолжит переписывать запросы в `web/`), но говорим приложению, что базовый
адрес пуст, - в **config/web-local.php**:

```php
<?php
return [
    'components' => [
        //адреса приложения перестают включать /web, хотя корень сайта прежний
        'request' => ['baseUrl' => ''],
    ],
];
```

Проверяем, что интерфейс открывается по чистому адресу и что старый адрес тоже жив:

```bash
curl -sI https://inventory.domain.local/techs/index | head -1
curl -sI https://inventory.domain.local/web/techs/index | head -1
```

После перехода:

- ссылки, которые рисует само приложение (включая ссылки в wiki-плагине и в письмах), становятся
  чистыми - интеграции можно переводить на них по мере возможности;
- у сотрудников, залогиненных до перехода, в браузере остается кука сессии со старым путем
  `/web`. Обычно это незаметно, но если после перехода наблюдаются странности с авторизацией -
  достаточно почистить куки сайта и залогиниться заново;
- когда ни одна интеграция больше не ходит на `/web/...`, совместимость можно выключить
  ([как](install.md#адреса-приложения)).

### Если что-то пошло не так

Ну или просто раньше было лучше. Тогда в обратном порядке делаем:

#### Откат БД

Нужно делать, только если при обновлении БД были применены какие-то миграции.
Итак, нужно отменить последние миграции. Может быть вы помните сколько было применено, но на всякий случай смотрим историю миграций:

```bash
./yii migrate/history
```


#### Откат файлов

делаем git checkout на старый коммит:

```bash
git checkout c729a2b43520275f1abc8c25bd9770f5d6c43519
```

после чего git правда скажет, что мы находимся в состоянии detached HEAD (отцепились от ветки).

Не забываем откатить и зависимости под старую версию кода:

```bash
composer update
```

#### Вернуться на последнюю версию

надо вернуться на ветку и обновиться:

```bash
git checkout master
git pull
composer update
./yii migrate
```
