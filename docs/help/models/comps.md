# Операционные системы

Ручную инвентаризацию железа ([оборудования](techs.md), [ЗИП и Материалов](materials.md)) дополняет полуавтоматическая инвентаризация Операционных систем.
Есть несколько типов скриптов, собирающих информацию об установленных ОС:

- [Импорт скриптами из Windows](https://github.com/spo0okie/win-inventory) — Сканирует установленное железо, софт, IP адреса — распространяется по операционным системам Windows при помощи GPO
- [Импорт скриптами из Linux](https://github.com/spo0okie/puppet_inventory_scripts) — Сканирует установленное железо, IP адреса — распространяется по операционным системам Linux средствами управления конфигурациями (например Puppet)
- [Импорт скриптами из VMWare](https://github.com/spo0okie/powercli_inventory_scripts) — Сканирует установленное железо, IP адреса, раскладывает операционки по [АРМам](techs.md) согласно расположению ВМ на хостах, работает с одного узла с установленным PowerCLI

## Список

Список сортируется (клик по [заголовку](<#doc-select:.grid-view th a[data-sort]>))
и фильтруется [полями ввода под заголовками](<#doc-select:.grid-view .filters input>)
(подсказка по фильтру — "?" в заголовке). Цвет [ячейки с именем
хоста](#doc-select:td.arm_hostname) показывает давность последних данных
от скрипта инвентаризации (легенда цветов — в подсказке заголовка).

> Из неочевидного - **поиск по софту/железу**: текст, вписанный в поле
> ["ОС/Софт"](<#doc-select:.grid-view .filters input[name="CompsSearch[os]"]>),
> ищется не только в [отпечатке софта](comps/raw_soft.md), но и в
> [отпечатке железа](comps/raw_hw.md). Так можно найти ОС по серийнику
> материнской платы, модели платы, версии конкретной программы и т.п.

## Просмотр

Карточка ОС собрана из блоков:

- **шапка** — имя хоста со [значком удалённого
  доступа](#doc-anchor:remote-control), [ярлычок давности
  данных](#doc-anchor:updated-age) (клик разворачивает дату обновления и
  [версию скрипта](comps/raw_version.md)), версия ОС, ответственный и
  команда поддержки, комментарий;
- **[привязки](#doc-anchor:bindings)** — АРМ или платформа виртуализации,
  IP-адреса и MAC, привязанные лицензии;
- **[сервисы и обслуживание](#doc-anchor:services-maintenance)** — в работе
  каких сервисов участвует ОС, требования и работы по обслуживанию;
- **[доступы](#doc-anchor:access)** — ACL и учётные записи (ACE);
- **[журнал входов](#doc-anchor:login-journal)** — три последние записи
  входа пользователей;
- **[железо](#doc-anchor:hardware)** — распознанный
  [отпечаток железа](comps/raw_hw.md), обнаруженного внутри ОС;
- **[софт](#doc-anchor:software)** (правая колонка) — обнаруженное ПО
  по категориям согласования;
- **[дубликаты](#doc-anchor:dupes)** — подозрения на записи-двойники
  (с таким же именем хоста в этом окружении) с кнопкой поглощения.

Значения полей и назначение элементов поясняют их собственные подсказки
(иконка «?» у поля, тултип у значка) — здесь только состав карточки.

### Удаление

Удалить ОС ([кнопка-корзина](<#doc-select:.comps-view h1 .delete-item-button, .comps-view h1 .fa-lock>)
в шапке карточки; при наличии связанных объектов вместо неё замок —
тултип перечислит, что мешает) можно, если

- история об ОС абсолютно точно не нужна, например временно развернутая виртуалка на пару дней
- просто дубликат какой-то ошибочный

В остальных случаях правильнее [архивация](comps/archived.md).

## Редактирование

Назначение полей показывают подсказки прямо в форме. Типовые сценарии
ручной правки:

- **обычное рабочее место** — руками меняются только
  [FQDN](#doc-select:.field-comps-domain_id,.field-comps-name) (Домен +
  [Имя компьютера](comps/name.md), например при переименовании машины
  или переводе в другой домен; там же — как правильно переименовывать)
  и [привязка](#doc-select:.field-comps-arm_id) к [АРМ](comps/arm_id.md):
  сопоставление ОС с железом делается вручную;
- **сервер** — дополнительно правятся [Сервисы и
  обслуживание](#doc-select:.field-comps-services_ids,.field-comps-maintenance_reqs_ids,.field-comps-maintenance_jobs_ids);
  [Пользователь](comps/user_id.md)
  ([поле](#doc-select:.field-comps-user_id)) заполняется только для
  ВМ-рабочих мест.

Поля под кнопкой **["Расширенные настройки"](#doc-anchor:advanced-settings)** (версия ОС, IP- и MAC-адреса,
[отпечаток железа](comps/raw_hw.md), отпечаток софта, внешние ссылки)
заполняются скриптами инвентаризации — внесённое руками скрипт, скорее всего, затрёт при следующем
срабатывании.

Выведенную из работы ОС не удаляем, а [архивируем](comps/archived.md).
