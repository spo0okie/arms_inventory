# Требования по обслуживанию → Доп. связи

JSON-структура с произвольными машиночитаемым описанием требований по обслуживанию.
При записи новые узлы объединяются со старыми (перезаписывается только
то, что указано; удаление узла — запись пустого значения).

Может удобно использоваться внешними интеграционными скриптами.

Продукт не навязывает состав ключей — организация
договаривается о своей схеме и строит на ней собственную автоматизацию.

## Пример использования

Машиночитаемая часть требования резервного копирования - то, что в
описании требования описано для людей, здесь продублировано для скриптов:

```json
{
  "backup": {
    "class": "vm",
    "gfs": {"days": 7, "weeks": 0, "months": 3, "years": 0}
  }
}
```

- `class` - класс резервной копии, которую требует это требование:
  - `vm` - резервная копия ВМ целиком (типовой случай);
  - `file` - файловая резервная копия (выгрузка БД, файлы сайта);
- `gfs` - GFS-сценарий Д-Н-М-Г: сколько хранится дневных, недельных,
  месячных и годовых копий. Нулевые слои можно опускать.
