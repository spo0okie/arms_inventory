# Операционные системы → Отпечаток софта

JSON-объект с железом, обнаруженным внутри ОС. Заполняется скриптом
инвентаризации; руками менять не нужно — при следующем срабатывании скрипт
перезапишет значение.

Строго говоря, это не совсем валидный JSON: не хватает обертки из квадратных
скобок `[]`, т.к. это массив устройств. В валидном виде выглядит примерно так:

```javascript
[
  {"publisher":"The Document Foundation", "name":"LibreOffice 7.4.1.2"},
  {"publisher":"Microsoft Corporation", "name":"Microsoft Update Health Tools"},
  {"publisher":"CANON INC.", "name":"Canon MF240 Series"},
  {"publisher":"Microsoft Corporation", "name":"Update for Windows 10 for x64-based Systems (KB5001716)"},
  {"publisher":"CANON INC.", "name":"Canon MF Scan Utility"},
  {"publisher":"\"Лаборатория Касперского\"", "name":"Агент администрирования Kaspersky Security Center"},
  {"publisher":"Корпорация Майкрософт", "name":"Microsoft Edge"},
  {"publisher":"IBM", "name":"Lotus Notes 8.5.3 (Basic) ru"},
  {"publisher":"АО \"Лаборатория Касперского\"", "name":"Kaspersky Endpoint Security для Windows"},
  {"publisher":"Microsoft", "name":"Майкрософт Windows 10 Pro"}
]
```

Интересна не сама JSON строка, а то, что система из неё
делает: [блок **«Софт»**](#doc-anchor:software) на карточке ОС.

## Категории согласования

Каждая строка отпечатка сопоставляется с [продуктом (ПО)](../soft.md)
и раскладывается
по категориям — сверху вниз от «неинтересных» к требующим внимания:

- **Игнорируемый** — продукт входит в служебный список ПО `soft_ignore`
  (справочник «Списки ПО»: системные компоненты, драйверы и прочий шум).
  Свёрнут; заголовок-тогглер раскрывает список.
- **Бесплатный** — продукт из списка `soft_free`: лицензионный учёт не
  нужен. Тоже свёрнут.
- **Согласованный** — продукт из списка `soft_agreed`: разрешён
  к использованию.
- **Требующий согласования** — распознанный продукт, не входящий ни
  в один из служебных списков. Это рабочая очередь: софт нужно либо
  согласовать, либо запретить/удалить.
- **Не распознанный** — строки отпечатка, которые не удалось сопоставить
  ни с одним продуктом. Кнопка «Создать продукт из этого элемента»
  заводит новый продукт прямо из строки; после появления продукта строка
  при следующем рескане попадёт в одну из категорий выше.

Кнопка «Вписать ПО в паспорт» у распознанного элемента закрепляет продукт
за этой ОС — он попадает в [паспорт АРМ](../../guides/arm-passport.md).

Если правила распознавания изменились (заведён новый продукт, продукт
добавлен в список), отпечаток пересчитывается не мгновенно — ОС попадает
в очередь рескана (плашка над блоком «Софт» показывает состояние).
