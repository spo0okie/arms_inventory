# DNS-имена

DNS-имя — запись в зоне (домене), указывающая на набор IP-адресов:
`имя в зоне → адреса`. Зона берётся из справочника доменов — он и так
описывает DNS-зону (NetBIOS-имя + полное имя зоны).

У [ОС](comps.md) и [оборудования](techs.md) уже есть собственное имя —
hostname в домене. DNS-имена это имя **не заменяют, а дополняют**: сюда
заводится то, чего у узла нет.

- **Алиасы** узла: `git.corp.example` рядом с hostname `gitlab01`.
- **Имена сервисов на реверс-прокси**: одно имя на прокси, за которым
  живёт бэкенд с другим именем.
- **Имена на белых адресах**: внешнее имя указывает на публичный IP, у
  которого нет узла в инвентаризации (облачный NAT).

К чему относится имя (узел, сервис), отдельно не указывается — это
выводится через адреса: имя → [IP-адрес](net-ips.md) → ОС/оборудование →
сервис. Поэтому у имени нет собственных ссылок на узлы и сервисы.

## Адреса

Одно имя может вести на несколько адресов, несколько имён — на один.
Адреса вводятся [текстом по одному в строке](#doc-select:.field-dnsnames-ip),
как у оборудования; при сохранении они попадают в реестр IP-адресов
(отсутствующие создаются). Пустой набор допустим: имя заведено, но ни на
что не указывает (парковка, ещё не поднятый сервис).

Адрес, на который указывает DNS-имя, не удаляется из реестра сам, пока
имя на него ссылается.

## Зона и полное имя

В поле [«Имя в зоне»](#doc-select:.field-dnsnames-host) можно ввести полное
имя: `www.example.com`. Если суффикс совпал с полным именем одной из
заведённых зон (берётся самая длинная), зона подставится сама, а в имени
останется `www`. Пустое имя — запись на саму зону (apex).

Имя внутри зоны уникально. Совпадение с hostname ОС или оборудования в
той же зоне не запрещено.

## Карта зоны

Карточка домена собирает все имена зоны в один список: hostname ОС,
hostname оборудования и DNS-имена, отсортированные по имени, с иконкой
типа и адресами. Список имён во внешней зоне (например, чтобы поставить
TLS на мониторинг истечения) — это карточка внешнего домена.
