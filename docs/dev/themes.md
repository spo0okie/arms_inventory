# Темы оформления (для разработчиков)

Механизм светлой/тёмной темы и правила, по которым пишется весь новый
CSS приложения. Здесь — архитектура, сборка и конвенции; краткая
обратная карта «элемент → источник» — в [ui-sources.md](../../ui-sources.md)
§10.

Смежное:
- целеполагание и история решений — в git (план `plans/themes.md` до
  переноса, коммиты августа 2026);
- пользователю документация не нужна: переключатель в navbar
  самоочевиден (Светлая / Тёмная / Как в системе).

## 1. Механизм

Штатные цветовые режимы Bootstrap 5.3: атрибут `data-bs-theme="<тема>"`
на `<html>`, тема = набор CSS-переменных. Добавление темы не трогает
ни разметку, ни PHP.

Ключевое ограничение: **серверный HTML одинаков для всех пользователей
и обеих тем** (требование кэшируемости, см. принцип «кэш требует
одинаковости HTML»). Поэтому всё переключение — на клиенте:

- `views/layouts/theme-init.php` — инлайн-скрипт **первым** в `<head>`
  обоих полных layout'ов (`main.php`, `embed.php`): ставит атрибут до
  загрузки CSS и первой отрисовки (иначе мигание светлым — FOUC).
  Выбор хранится в `localStorage.armsTheme`: `light` | `dark` | `auto`
  (по `prefers-color-scheme`, со слежением за сменой системной темы
  на лету). Дефолт **временно `light`** — до завершения обкатки тёмной,
  потом вернуть `auto` (помечено в самом файле);
- переключатель — dropdown в правом Nav `views/layouts/menu.php`
  (пункты `a[data-set-theme=...]`); активный пункт помечает тот же
  скрипт — сервер про тему не знает.

Печать всегда светлая: все тёмные правила `themes.css` завёрнуты в
`@media screen` (паспорта АРМ, сканы, наклейки).

## 2. Слои CSS

### 2.1 Бутстрап-слой: сборка из SCSS

`web/css/custom.css` — это **сборка**, не рукописный файл (правки руками
в него не вносить; файл коммитится, деплой ничего не собирает):

```
scss/custom.scss
  ├─ _arms-variables.scss   наши отличия от Yeti + палитра тёмной ($*-dark)
  ├─ bootswatch/…/yeti/_variables.scss   (npm: bootswatch)
  ├─ vendor/twbs/bootstrap/scss/bootstrap (версию пинит composer)
  ├─ bootswatch/…/yeti/_bootswatch.scss
  └─ _arms-overrides.scss   локальные правки поверх темы
```

Сборка: `npm run css` (или `npm run css-watch`); тулчейн — `package.json`
(dart-sass; `chokidar` запинен на v4 — v5 ESM-only не заводится на
node 22.9). Порядок импортов важен: наши переменные идут **до** йетиных —
у Yeti всё под `!default`, побеждает первое определение.

Тёмный режим бутстрап-компонентов компилируется самим бутстрапом
(`$enable-dark-mode`, палитра — `$body-bg-dark` и прочие `$*-dark` в
`_arms-variables.scss`, сине-серая гамма тёмной шапки page-header.css).

Дист-бутстрап при этом **не грузится** — `BootstrapAsset.css=[]` в
`config/web.php` (иначе бутстрап приезжает дважды). Там же
`assetManager.appendTimestamp = true` — кэш-бастер `?v=<mtime>`: без
него браузеры держат старый CSS после деплоя.

Внешних запросов у сборки нет: `$web-font-path: false` (Open Sans из
Yeti нигде не применялся, тело набрано Helvetica), все шрифты локальные
(`web/fonts`, `web/fontawesome`).

### 2.2 Слой приложения и виджетов: `web/css/themes.css`

Всё, чего сборка не покрывает. Подключается в `AppAsset` **последним** —
его правила должны перебивать и `custom.css`, и остальные прикладные
файлы. Содержит:

- токены слоя приложения `--arms-surface`, `--arms-surface-2`,
  `--arms-border`, `--arms-muted` (значения согласованы с `$*-dark`);
- точечные доводки бутстрапа, которые дарк-режим сам не делает
  (`btn-light`/`btn-secondary`, `border-secondary`, `table-light`,
  kartik-градиенты шапок гридов, `text-secondary` Yeti);
- тёмные значения токенов прикладных раскрасок (см. 2.3);
- тёмные варианты сторонних виджетов: select2 (krajee-bs5), tooltipster
  (оба варианта + стрелки по 4 направлениям), markdown-редактор kartik,
  блоки расписаний.

### 2.3 Прикладные раскраски: токены

Канон параметризации (главная конвенция):

> **Новый цвет в прикладном CSS — сразу токен**: дефолт токена = светлая
> тема, тёмное значение — в `themes.css` под `[data-bs-theme=dark]`.
> Захардкоженный светлый фон/цвет — это баг тёмной темы.

Действующие семейства:

| Токены | Что красят | Дефолты (светлая) | Тёмная |
|---|---|---|---|
| `--fresh-*` / `--fresh-*-strong` | свежесть данных ОС: ячейка списка / уголок unit-status | `state-colors.css` (исторические цвета) | themes.css: градиент «синий (свежее) → красный (устарело)» на палитре Yeti |
| `--map-*`, `--map-hatch*` | карта рабочих мест: типы оборудования, сетка, CSS-штриховка серверов/NAS | `arm-map.css` (исторические, ещё с гугл-таблицы) | themes.css: глубокие оттенки тех же смысловых hue |
| `--ipam-*` | IPAM: служебные ячейки вне маркеров (empty/occupied/nocode) | **фолбэками** `var(--ipam-empty, #aaa)` в инлайн-CSS `views/networks/ipam.php` | themes.css |
| `--ports-slot-*` | карта портов на корпусе (`PortsMapWidget`): фон/текст/рамка слота по состоянию опроса (`slot-ok`, `slot-quiet`…) | `arms.css` (оттенки bootstrap-subtle) | themes.css: приподнятая поверхность + глубокие оттенки тех же hue |
| `--marker-*` | цветовые маркеры справочника | инлайн-переменные от `Markers::getStyleVars()` | одинаковы в обеих темах (маркер сам несёт фон и автоконтрастный текст) |

Почему у IPAM дефолты фолбэками, а не в `:root`: инлайн-CSS вьюхи
регистрируется **после** `themes.css`, и `:root`-объявление перебило бы
тёмные значения (специфичность равна, позже — сильнее). Общее правило:
дефолты токенов кладутся туда, что в каскаде стоит **до** `themes.css`
(файлы `AppAsset`), иначе — фолбэком в `var()`.

Светлые палитры прикладных раскрасок — исторические, к ним привыкли:
**до завершения обкатки тем не менять**.

### 2.4 Легенды раскрасок

Легенду красить **теми же классами/токенами, что и сами элементы** —
тогда в каждой теме она показывает фактические цвета, а подписи цветов
могут быть приблизительными («жёлтый», даже если в тёмной он янтарный).
Живой образец — легенда свежести в `indexHint` атрибута `Comps.name`.

## 3. Как добавить новую тему

1. Блок `[data-bs-theme="имя"] { … }` в `themes.css` с переопределением
   токенов (образец — тёмная);
2. пункт в переключатель `menu.php` (`a[data-set-theme="имя"]`);
3. `theme-init.php` менять не требуется (значение из `data-set-theme`
   просто попадает в localStorage и в атрибут).

Если теме нужны и другие бутстрап-переменные — по возможности через
токены/`--bs-*` переменные; пересборка SCSS нужна только для новых
*компилируемых* отличий.

## 4. Mermaid и прочий JS-рендер

Диаграммы mermaid в документации: тема выбирается при инициализации по
`data-bs-theme` (`dark` / `neutral`) — `components/assets/MermaidAsset/js/mermaid-init.js`.
При переключении темы на лету уже отрисованные диаграммы не
перекрашиваются — перерисуются при следующей загрузке страницы. Тот же
подход — для любого будущего JS-рендера, который красится на канве/SVG.

## 5. Готчи (проверено на практике)

- **SVG с `stroke="black"`/`fill="black"`** (схема коммутации в тултипе
  порта) в тёмной теме — чёрное на тёмном; писать `currentColor`, тогда
  рисунок наследует цвет текста бокса;
- **`background-image`-пятна**: светлые градиенты (kartik красит шапки
  гридов `linear-gradient`) и паттерны контраст-аудитом по
  `backgroundColor` не ловятся — проверять глазами/скриншотами;
- **Yeti-утилиты с `!important`** (`.text-secondary`, `.border-secondary`,
  `bg-light`/`text-dark` панелей) перебиваются только с `!important`;
- **Yeti задаёт `border-color` кнопок прямым свойством** мимо
  `--bs-btn-border-color` — тёмный оверрайд кнопок обязан ставить и
  прямое свойство;
- **стрелки tooltipster** — CSS-треугольники, красятся отдельными
  правилами по 4 направлениям (`.tooltipster-top/-bottom/-left/-right
  .tooltipster-arrow-border`); рамку бокса стрелка повторить не может;
- **`$table-bg: transparent`** (в `_arms-variables.scss`) обязателен: в
  5.3 фон таблиц стал непрозрачным — это белые ячейки в тёмной шапке и
  затёртые цветные ячейки (state-colors, маркеры);
- **смешанные ячейки IPAM**: контрастный цвет подписи считается на
  сервере от светлого `#FFFFFF` (HTML один для тем) — в тёмной долю
  nocode искажает; выручает ореол `--ipam-shadow`;
- **проверка в browser-панели**: CSS-transition в скрытой панели
  «замерзают», а скриншоты могут отдавать устаревший кадр — истина
  всегда в computed styles (CSSOM), кадр обновляется скроллом.

## 6. Состояние обкатки

- дефолт темы `light` — после обкатки вернуть `auto`
  (`theme-init.php`, помечено комментарием);
- светлые палитры прикладных раскрасок не менять (см. 2.3);
- DokuWiki-плагин (`doku_inventory`) темами не охвачен — отдельная
  задача (его ассеты синхронизируются из ARMS, см. sync_assets.sh).
